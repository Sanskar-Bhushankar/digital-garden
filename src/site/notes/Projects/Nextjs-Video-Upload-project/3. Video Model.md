```js
import mongoose, { Schema, model,models } from 'mongoose';


export const VIDEO_DIMENSIONS={
    width: 1080,
    height: 1920,
}as const;

export interface IVideo {
    _id?: mongoose.Types.ObjectId;
    title: string;
    description: string;
    videoUrl: string;
    thumbnailUrl: string;
    controls?: boolean;
    transformation?: {
        width: number;
        height: number;
        quality?: number;
    }
}

const videoSchema = new Schema<IVideo>(
    {
        title: {type: String, required: true},
        description: {type: String, required: true},
        videoUrl: {type: String, required: true},
        thumbnailUrl: {type: String, required: true},
        controls: {type: Boolean, default: true},
        transformation: {
            width: { type: Number, default: VIDEO_DIMENSIONS.width },
            height: { type: Number, default: VIDEO_DIMENSIONS.height },
            quality: { type: Number, min:1,max:100 } // Default quality
        }
    },
    {
        timestamps:true
    }
)

const Video = models?.Video || model<IVideo>('Video', videoSchema);
export default Video;
```

### import mongoose, { Schema, model, models } from 'mongoose'

You are importing:

* `mongoose`: the main library to work with MongoDB.
* `Schema`: to define the shape of your data.
* `model`: to create a model based on your schema.
* `models`: to check if a model already exists (avoids errors during development hot-reload).

---

### export const VIDEO\_DIMENSIONS = { ... } as const

This is a constant object that defines default video dimensions:

* `width: 1080`
* `height: 1920`
  `as const` locks the values so they can’t accidentally be changed later.

Why?
You use these as defaults in your schema’s `transformation` field.

---

### export interface IVideo

This is a **TypeScript interface** that defines the shape of a Video document:

* `_id?`: optional MongoDB ID.
* `title`: string, required.
* `description`: string, required.
* `videoUrl`: string, required.
* `thumbnailUrl`: string, required.
* `controls?`: optional boolean (if video controls should be visible).
* `transformation?`: optional object with width, height, and optional quality.

This is only for **TypeScript type checking**. MongoDB does not care about it.

---

### const videoSchema = new Schema<IVideo>(...)

Here you define the actual MongoDB schema.
This tells MongoDB how a Video document should look and validates it when saving.

Fields explained:

* `title`, `description`, `videoUrl`, `thumbnailUrl`: all are required strings.
* `controls`: boolean, defaults to `true`.
* `transformation`:

  * `width`: number, default from `VIDEO_DIMENSIONS.width`.
  * `height`: number, default from `VIDEO_DIMENSIONS.height`.
  * `quality`: optional number between 1 and 100.

`timestamps: true` automatically adds `createdAt` and `updatedAt` fields.

### const Video = models?.Video || model<IVideo>('Video', videoSchema)

This creates the Video model from your schema:

* `models?.Video`: checks if the model already exists (avoids errors during hot reload).
* `model<IVideo>('Video', videoSchema)`: creates a new model using `IVideo` for type safety.

### export default Video

This exports the model so you can import it in other files and use it like:

```ts
import Video from './models/video'
const newVideo = await Video.create({...})
const videos = await Video.find({})
```


### Summary of flow


| Step                   | Why?                                              |
| ---------------------- | ------------------------------------------------- |
| `IVideo`               | TypeScript blueprint for Video object.            |
| `videoSchema`          | MongoDB schema defining field types and defaults. |
| `VIDEO_DIMENSIONS`     | Default width and height for transformations.     |
| `Video` model          | Combines schema and type into usable model.       |
| `export default Video` | Allows importing and using the model elsewhere.   |
